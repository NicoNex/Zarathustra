# Kobo Port Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Zarathustra runs on the Kobo Clara 2E from NickelMenu (reading, light, sleep, USB, Wi-Fi, SSH), and adding the next device means one backend module, one platform entry and one launch script.

**Architecture:** One static binary. `zarathustra_device::platform()` says where things live (detected once from the filesystem); `open_default()` opens the matching `Device` backend. The shell reads the screen size and platform facts at runtime instead of the PW5 constants and `/mnt/us` paths. The Kobo backend (`kobo/`) reuses the shared touch decoder, sysfs helpers, a framebuffer back buffer split out of the MTK driver, and a `wpa_cli` module split out of the Kindle Wi-Fi.

**Tech Stack:** Rust (musl armv7 static), libc ioctls (mxcfb Mark 7), evdev, sysfs, `wpa_cli`/`wpa_supplicant`/`dhcpcd`, POSIX sh launch scripts, NickelMenu.

**Spec:** `docs/superpowers/specs/2026-11-09-kobo-port-design.md`

## Global Constraints

- Kobo only today: no Kindle deploys or device tests; the Kindle build must still compile and its tests stay green.
- CLAUDE.md gates before every commit: `cargo fmt --all`, `cargo clippy --workspace --all-targets --all-features` with zero warnings, `cargo test --workspace`. Every `unsafe` documented. No `unwrap()` outside tests.
- Never copy code from KOReader, Plato or FBInk (references for facts only: ioctl numbers, struct layouts, sysfs paths, module names). Local clones for reading: the session scratchpad `ref/` dir, or clone again (`github.com/koreader/koreader`, `github.com/baskerville/plato`, `github.com/NiLuJe/FBInk`).
- Missing capabilities never change the UI: same screens on every device; a tile/button whose capability is missing stays and a tap does nothing.
- Kobo layout: app files in `/mnt/onboard/.adds/zarathustra/` (bin, hyph, state, plugins, dictionaries, fonts, scripts, logs); books in `/mnt/onboard/library/`; fonts also from `/mnt/onboard/fonts`.
- Exit-status contract shared by both launch scripts: `0` quit (bring the vendor UI back), `42` hand the storage to a computer over USB then start again (`USB_EXIT` in app.rs), update flag file → start the new binary again.
- Never commit device data (SSIDs, passwords, MACs, IPs, serials). Probe output stays on the device/in the scratchpad.
- Shortcuts get `// shortcut: <limit>, <when to upgrade>` comments (CLAUDE.md's `ponytail:` form is also accepted).
- Talk to the user in Italian; code, comments, commits in English. Commits are Conventional Commits.

## Review Focus

1. **Launch script dies or the app crashes** → Nickel must come back (or the device reboots); a Kobo left with a frozen screen and no UI is the worst outcome. Test: Task 4 step "kill -9 the app" on the device.
2. **Cable pulled during the USB export / storage dirty** → the script runs `dosfsck` before remounting and the app was not running while exported (no SQLite file open on `/mnt/onboard`). Test: Task 7 device check unplugs mid-copy.
3. **Wi-Fi bring-up fails half-way** (module loaded, no supplicant, no DHCP) → `connect`/`set_enabled` return an error within a bounded time, the UI shows the existing error path, quitting leaves the radio off so Nickel starts clean. Test: Task 8 unit test on the timeout + device check with a wrong password.
4. **Layouts at 1072 px wide** → labels clipped or rects overlapping in quick panel, keyboard, Wi-Fi, footnote card, prefs. Test: Task 1 renders every `--pgm` screen at 1072×1448 and they are looked at.
5. **Wake without the power button** (USB plug, charger, RTC) while asleep → the sleep screen stays and the device suspends again; no half-awake state with touch live and light off. Test: Task 6 device check plugs the charger while asleep.
